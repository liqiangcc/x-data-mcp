# Issue #239 — .day volume/amount 单位语义锚定（TQ oracle）

**结论：`.day` 第 6 字段 `amount` = 元（f32），第 7 字段 `volume` = 股（u32）。**
「股/元」假设成立；「手/千元」被排除。

## 方法

分辨规则（issue 给定）：外部显示「股/元」→ 直接相等；「手/千元」→
×100 / ×1000。TQ oracle 提供两个独立表面：

- **type=1 日线** (`get_market_data`/`GetTdxDataStr` type=1)：`Volume`
  逐 bar，`Amount` 逐 bar
- **type=3 快照** (`get_market_snapshot`)：`Volume`、`Amount`、
  `LastClose` 等当日字段
- 客户端 UI 十字线读数 `VOLUME`（#166 同款显示路径）

## 证据

### 1. 冻结 6 证券全历史比对（gen-3 hsjday.zip × TQ type=1）

37,345 根可比日线（600004/600006/000001/000002/000035/688318）：

- **volume**：31,343 根逐位相等；其余 6,002 根的差值 **全部**
  恰好等于 `float32(.day u32)` 的量化误差（TQ 经 f32 通道服务，
  >2²⁴ 的整数股数必然失真）。股语义 100% 成立。
- **amount**：`.day f32 / 10000` 与 TQ `Amount`（万元，2dp）在
  `f32 ULP/2 + 0.005万` 界内一致 37,288/37,345；57 根残差
  ≤30元（相对 ~1e-6，疑似上游独立取整/更正），不构成单位分歧。

### 3. type=3 快照第二表面（600000 @2026-09-18，verbatim `raw/snapshot_600000.json`）

- `Volume = "517592"` = `.day volume // 100` → 快照用 **手**
  （与 K线接口的「股」不同——同一 API 族内部单位不一致，如实记录）
- `Amount = "46996.94"` 万元，与 K线一致
- 客户端十字线 `VOLUME: 517593`（手，四舍五入显示）亦自洽

### 4. TQ 字段清点（供 #240）

- type=1 日线字段：`Date,Time,Open,High,Low,Close,Volume,Amount,
  VolInStock,ForwardFactor` — **无 昨收/preclose/除权基准字段**
- type=3 快照含 `LastClose`（昨收），但**仅当日**：今日 600000
  `LastClose=9.06` = 原始前收（非除权日）。除权日的 `LastClose`
  即交易所/官方除权基准价 → r7 语义的**前瞻性** oracle 路径存在
  （如 sz.000001 除权日 2026-09-24 可实测），不能回溯历史 r7。

## 边界

- 所有比对为诊断证据，不直接等于发布许可；volume/amount 晋升仍走
  实现 issue + 治理流程。
- TQ 数值经 f32/万元/2dp 服务通道，单位锚定成立但不应据此推断
  .day f32 的生成顺序（先取整后 f32 化 vs 反之不可分辨）。
