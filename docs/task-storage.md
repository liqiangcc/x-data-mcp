# 任务受理提交点（#58）

`task-state.json`统一保存bindings、executions、occupancy。新受理先在内存中构造三者，
序列化到同目录临时文件并sync，然后以一次rename替换正式文件。受理错误不再留下单独的
request绑定。复用已有request时检查执行记录，以及未结束任务的完整占用；不完整则明确
返回ACCEPTANCE_NEEDS_VERIFICATION，不自动放行、重新派工或伪造成功。

新文件不存在时只读既有三个legacy文件，之后正常写入以整体快照保存三者，不删除legacy。
新文件存在但损坏/不可读时不回退到legacy或空状态。历史未结束绑定即使丢失occupancy，
其范围也保守地视为占用；需独立有证据的恢复才能解除。未迁移任何真实运行数据。

执行状态更新与占用更新分别是原子快照写入；既有业务顺序不变。终态释放仍由原用例负责。
这不是跨进程并发事务实现；当前服务须单写者运行。保证范围与行情存储一致：Linux同文件
系统的进程崩溃原子可见性，不声称已验证断电耐久性或多写者并发。崩溃遗留临时文件不参与读取。

回归覆盖三种原legacy写入受阻、同request重试、重启后占用与不同request重叠拒绝、历史
残缺绑定拒绝复用、损坏新状态拒绝回退。公共原子写入帮助函数另有部分暂存失败保留旧状态测试。
来源门禁和normalization均未变化，live source NOT_RUN。
