# 已发布版本完整性读取（#66）

> **历史文档（JSON 文件存储时期）。** 下文把「按 `version_id` 读取某个历史版本」「列表按提交次序」作为
> 完整性读取的前提，这是版本链模型（schema 20 及更早；已被 schema 21 取代，历史）。当前部署的
> schema 21 单版本模型不再保留历史版本：`version_id` 是当前内容摘要（`hex(content_digest)`），旧
> `version_id` 读取返回 `stale_version`（曾存在）或 `version_not_found`（从未存在），**不回退到旧内容**；
> 完整性校验的对象从「版本记录摘要」变为序列的顺序折叠摘要（schema 21 自 preview.32 起部署）。
> 见 [单版本（latest-only）行情存储模型](latest-only-storage.md)。

新发布的每个记录包含integrity_sha256，对该记录除摘要字段外的完整JSON值计算SHA256。
使用serde_json默认有序键映射的紧凑序列化作为规范表示；价格仍为十进制字符串。
摘要覆盖version与关联原batch。历史记录以原JSON值保留，追加不会通过旧Rust结构重写未知字段。
摘要检测意外内容变化，不是签名、官方来源认证或对恶意存储管理员的防篡改保护。

`get_verified_version`显式version_id只在指定证券/周期/adjustment内查找；不存在、重复身份、
摘要缺失/不符、解码失败或身份不符均明确报错，无latest fallback。不指定id时只选择最后
提交记录，损坏不能退回旧版本。无文件时默认查询返回None，显式id查询报NotFound。
`list_verified_versions`按提交次序读取，任何不能确认的记录使完整列表请求失败；显式查询
同一可解码文件中的另一个完整版本仍可成功。该原语不等于最终MCP列表分页/排序契约。

旧无摘要记录的兼容读取接口仍保留，新的可验证读取接口拒绝把它当已核验数据。只读不自动
迁移、修复、回滚或重新采集，不创建空目录或文件。后续MCP查询必须使用可验证入口，并额外
兑现单位、覆盖、固定分页及derived yearly元数据契约。数据完整性与全历史行情覆盖是两回事。
