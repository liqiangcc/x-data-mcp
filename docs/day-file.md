# .day 原始解析（#64）

Rust `day_file::parse`按已有hsjday结构证据读取固定32字节little-endian记录。
仅转换可验证的日历日期；四个OHLC uint32、amount float32位模式、volume uint32和第8字段
(`r7_raw`)全部保留。零值和非有限float位模式不静默过滤。volume（股）/amount（元）语义经
#239 TdxQuant oracle锚定后晋升入发布bar，原值直存、不经QFQ调整；`r7_raw`仅以原始u32
入库（#240：A股1999–2010为官方除权基准价fen，基金/指数语义未锚定，2010-09后官方退化为
0x10000），不进查询契约。
截断、无效日期、重复/倒序会拒绝。空文件可结构解析为空，**不表示覆盖完整或可发布**。

**「手日」例外（#381）：** 当日成交量接近 u32 上限时 TDX 改按「手」记录（1 手 = 100 股），
同时把 `r7_raw` 写成 `0xC36400xx`。发布前按两项独立事实判定：`r7_raw` 高位标记，以及用
`.day` 原始值（不复权）做的校验「最低价 ≤ 成交额 ÷（volume × 100）≤ 最高价」。两项同时成立
才换算为股（×100）；只有标记、校验不过，或校验通过却没有标记，都判为「单位无法确认」，该 bar
的 volume 发布为未知（`null`），不猜。手日换算出的成交量只精确到 100 股，现有契约没有逐 bar
精度字段表达这一限制。`r7_raw` 无论判定结果一律保留原值。

`cargo run --locked --bin inspect_day -- /path/to/sh600006.day`只读取显式本地文件，输出
SHA256、字节数、记录数和首末日期。无网络、无发布、无Python依赖、无十进制规范化或QFQ。

有界retained验证重用#53四个已选官方成员，比较官方保留hash、记录数和日期范围。该验证说明
Rust解析与既有结构证据一致，不把社区逆向格式提升为官方业务契约。文件快照一致性、目录及
获取使用授权仍未完成。OfficialFilePipeline门禁未变。

**与存储层的关系（M1，代码已合并、未部署）：** 不复权序列就是本文件解析出的原值——OHLC 原样、
volume 按 #381 归一后发布、`r7_raw` 原样保留，不再做任何变换；前复权序列是**派生数据**
（`qfq-exact-v1`：精确有理数链、末次一次舍入，最多 6 位小数），可从「不复权 bar + gbbq cat1
事件」重算（`src/qfq.rs:204`；`migrations/tasks/022_research_data.sql:31-99`）。MCP 读路径目前
只解析前复权序列（`adjustment=1`），不复权只经研究快照导出可见（[数据目录](data-catalog.md) §5.3）。
