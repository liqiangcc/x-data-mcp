# 原子计算能力与 AI 编排边界

## 决策与状态

2026-09-12 用户明确：“边界就是 MCP 提供原子能力，AI 可以编排”，随后授权推进设计。
本节承接 #75 / PR #76，补充目标工具 compute_metrics。所有接口及指标均为待实现设计，
具体指标是否进入首期实现由后续任务决定，不因本文例子自动承诺交付。

## 职责边界

| 主体 | 负责 | 不负责 |
|---|---|---|
| AI | 研究目标、选择数据与算法、显式采集、组合调用、解释结果 | 猜测事务是否提交、绕过权限和发布规则 |
| MCP Adapter | 类型化参数、能力发现、结构化结果/错误 | 隐藏分析策略、自动修复数据 |
| 计算用例 | 固定输入、读取校验、资源控制、执行已选算法 | 缺数据时采集、换源、替换版本 |
| 纯算法 | 明确输入和参数到确定结果 | SQL、网络、时钟、任务调度 |
| 任务/存储基础设施 | 长计算受理、取消、持久结果、事务 | 选择指标或给出买卖结论 |

原子能力是语义完整的业务动作，不等于一次底层 I/O。
采集内部的下载/解析/校验/发布由服务控制；数据库事务不暴露为 AI 多次调用。
compute_metrics 可在同一固定输入上执行多个无依赖指标，这仍是一个“计算明确指标集合”的动作；
不接收指标 DAG、自然语言策略、任意代码/SQL，不暗中执行其他 MCP 工具。
跨工具组合无全局事务和自动回滚；某次失败不撤销之前成功采集的数据。

确定性计算不包括开放式研究解释、预测推荐、订单或回测撮合。
未来回测须独立明确成交、费用、历史时点、仓位与事件语义。
服务可以明确报告数据限制，但不替 AI 决定应采用哪种研究假设。

## compute_metrics 输入契约

目标字段：

| 字段 | 约束 |
|---|---|
| contract_version | 必填，计算请求契约版本 |
| inputs | 非空命名输入列表，每项 input_id 唯一，包含完整 DatasetVersionRef |
| range | 主结果区间；按 dataset 的日期/年度等类型定义 |
| metrics | 非空闭合类型列表，metric_id 唯一；name、algorithm_version、input_ids、parameters |
| execution | 必填 inline 或 task；没有自动切换模式 |
| request_id | task 必填，inline 不允许 |

input_id 是算法角色引用，不是文件路径。version_ref 必须包含 dataset、对应数据契约版本、
entity 和明确 version_id；目标初版不接受 latest，避免同一请求结果随时间变化。
多个输入由算法声明角色与匹配要求，不能只按数组位置猜测分子/分母等含义。
所有对象封闭校验，未知字段、重复指标 ID、不存在输入引用及不支持算法拒绝。

各 metric 使用 name + algorithm_version 判别的 schema 分支，
声明支持的 dataset、输入个数、单位/口径、参数与输出类型。
新增指标通常扩展注册分支和算法，不增加工具名称。
不对所有算法强行使用同一种 parameters 或通用任意表达式。

### 能力发现

get_data_capabilities 增加 operation=compute_metrics 的详情；可选 metric 名称筛选详细帮助，
这是目标 schema 扩展，现有代码不支持。
返回算法版本、输入角色、参数/输出 schema、公式、精度、预热需求、缺失策略、
资源上限、inline/task 支持情况与最小示例。
只有已注册且可执行的算法才可标为 implemented；帮助与 schema/算法注册同源。
数据来源门禁和指标语义验证分开：算法通过 fixture 不证明某个真实版本可用于计算。

## 数据不足、预热与精度

输出范围和读取范围明确分开。算法可以在同一个已指定版本内读取所声明的预热记录，
但必须在能力描述和结果中说明所需观察数及实际输入边界。
这不是隐式补采；不得读另一个版本补足预热。
若调用者指定严格输入边界，则边界外预热也不得读取，缺少时报告不可计算。

初版策略为严格拒绝缺少必需输入、日期对齐无法确认、单位/基准不一致、非有限输入或溢出。
不向前填充、不补零、不自动跳过缺失值。观察序列中的日期不连续并不等于缺数据，
是否满足算法输入条件由来源/日历/覆盖证据与明确观察规则共同决定。

基础值与中间运算使用明确数值类型。精确十进制除法可能不能有限表示：
不能把“使用 Decimal”称为所有结果数学精确。
每个算法冻结输出 scale、rounding 和中间运算策略；不可表示则报错，
或返回明确声明的舍入结果及精度元数据，禁止静默沿用库默认值。
涉及平方根等近似计算的后续算法必须标注近似性质和误差/舍入约定。

## 候选算法契约切片

这些是验证设计可落地的候选，不是已注册算法。正式 algorithm_version 发布前
须冻结精度和边界规则并通过独立计算样例。

| 候选 | 明确语义 | 边界 |
|---|---|---|
| period_return | 区间内首个与最后一个有效 close，返回 last/first-1 的比值；报告实际日期 | 至少两个观察值，first 必须大于 0；不是含现金分红再投资总回报 |
| max_drawdown | 按区间 close 序列，peak 为迄今最高 close；最大值为 1-close/peak，返回非负损失比值 | 要求 close>0；仅在区间内建立峰值，不包含未指定的区间前峰值 |
| moving_average | 明确 simple 类型，对连续 N 个已校验观察值的 close 求平均 | window>=1；是 N 个观察值，不是 N 个自然日；不足完整窗口不输出伪值 |

最大回撤需冻结并列峰谷的选择规则及是否返回恢复日期；初版不隐含恢复期指标。
均线输出按每个结果交易日期提供其实际参与边界，预热与结果区间分开。
QFQ 价格指标不直接等同真实投资组合收益或当时可获得的信息；返回相应口径限制。

## 输出和执行模式

inline 为有界同步计算，不创建持久任务、不写行情；允许进程内临时计算状态。
超过公开资源上限在执行前拒绝或在预算耗尽后返回明确错误，不暗中转成后台任务。
同一参数重算语义相同，但不是已消费 request_id 的幂等写请求。

task 显式异步受理，原子绑定 request_id、规范化输入/指标/契约并返回任务引用。
它读取源数据，但会写任务与结果记录，因此不能标成无持久副作用。
复用 get_request/get_task/get_task_progress/cancel_task；结果从对应 task_kind 的类型化结果字段读取。
大型序列可经固定计算结果 ID 分页，复用 get_task_progress 的结果分页分支；
该分支必须在实现前定义独立输出 schema 和 cursor 绑定，不能塞入不受限单响应。
初期未实现结果分页时，必须拒绝超出结果预算的请求，不能截断。

只读计算不占用数据写范围；必要的输入保留引用和计算资源配额与业务写占用分开。
同 request_id 跨采集/计算操作冲突，不能为计算另开逃逸命名空间。
后台取消不得改动源数据；结果不明按持久记录核实，不借用“发布行情”语义自动写入版本。

结果包含 calculation_id（或仅 inline 响应 ID）、契约版本、输入版本清单及摘要、
每指标算法版本/参数、实际输入范围、结果范围、观察数、单位、精度与限制。
指标值可为标量或类型化序列，返回 metric_id 以对应请求。
运行时间/任务 ID 是执行元数据，不参与确定性数值断言。

初版多指标采用全部成功才返回成功结果的策略；一个指标缺输入或失败时整体明确失败，
不提供看似完整的混合结果。错误列出失败指标和原因，可保留诊断，但不发布部分指标集。
AI 可显式拆请求计算其他指标，服务不自动替换参数。
若未来引入部分成功，需独立契约定义逐指标状态和总体 outcome。

持久任务结果是计算产物，不自动成为新的 published dataset。
若未来需要发布派生指标数据，另立明确的写入用例、质量门禁、血缘和保留规则。

## 正常组合示例

1. AI 查询能力和指标规则，选择研究对象。
2. get_data_availability 判断可用性；缺数据时由 AI 显式选择是否采集。
3. 采集完成后，AI 从任务结果或版本列表取得固定 version_ref。
4. compute_metrics 指定输入版本、指标与执行模式。
5. 数据不足则返回结构化 missing_requirements；AI 可停止、调整范围或另行采集，
   不能把错误提示视为自动扩大请求范围的授权。
6. AI 基于数值和限制解释结果；后续计算通过明确的输入版本或正式计算产物契约组合，
   不把任意自然语言分析文本当作标准数据版本。

## 验收与首期交付边界

- 同版本/同算法/同参数的数值和血缘确定一致；运行时间可不同。
- query/compute 缺数据时，没有下载、受理采集或写行情副作用。
- 输入版本损坏/不匹配明确拒绝，不读取其他版本。
- schema 分支、帮助示例、注册算法和处理器保持一致。
- Decimal 循环小数、除零、溢出、窗口不足、日期对齐及单位不一致有独立样例。
- 任务模式幂等、取消、结果预算和源版本保留引用可验证。
- 分离纯算法测试、执行/存储测试与 MCP 组合测试，不能靠自身实现生成期望值。
- 当前文档不指定未经测量的执行时限、记录上限，不宣称生产性能通过；
  实现前必须在能力描述中公开并测试资源预算。

本轮设计新增一个目标业务工具 compute_metrics；具体算法实现和首期范围通过
独立任务收敛，不默认同时开发全部候选。任意代码执行、自动研究策略和交易执行不在此工具内。

## 连续涨跌预制算法

[consecutive_direction 目标契约](preset-consecutive-direction.md)定义相邻收盘价连续涨跌、完整周期、持平/缺失处理、左边界下界与阈值三态结果。该能力通过 compute_metrics 注册，不新增工具；已纳入设计，尚未实现。布林线及比较/穿越仍为候选，算法口径与计算序列引用需要另行定稿。
