# 行情发布存储提交点（#57）

发布将原始候选batch与其有效version记录保存在同一个 `effective/<symbol>.<period>.qfq.json`
数组中。每个记录兼容既有version字段，并新增可选batch。读取旧数组不需要重写历史。
同目录临时文件写入完整内容并sync后，以rename替换正式文件；rename是唯一可见提交点。
在此之前发生序列化、写入或sync失败，原正式文件不变；之后不再执行第二次batch写入。

进程在rename之前退出，读者仍见旧完整文件（或无文件）；rename之后退出，读者见新完整文件。
遗留临时文件不参与读取。正常失败由tempfile清理。此处保障支持平台Linux同一文件系统上的
进程崩溃原子可见性；不把它宣称为已测试的断电/存储设备故障耐久性保证，目录元数据的断电
持久性仍取决于文件系统。该改动也不新增跨进程多写者锁或修订批准协议。

`get` 优先读取已提交记录中的batch；若为旧version且无batch，按version重建。
只有没有已提交version时，才读取旧独立batch路径。这样过时或受阻的旧batch文件不会覆盖
已发布事实。旧独立文件保持原样，不做真实数据迁移；`put`继续供独立离线batch存取使用，
不再被publisher调用，也不能覆盖已提交版本的读取结果。

回归包括原先的第二文件受阻案例（修复前FAIL）、重启后batch/version一致、旧batch不覆盖
新发布、部分暂存失败保留旧内容/缺失状态。来源gate仍不变，测试使用fixture，live来源NOT_RUN。
